## 2. 启动

### 方式 A：本地直跑（Windows）

```bash
cd D:\Rag_project\E-commerce_Customer_Service_System
.venv\Scripts\activate

# 1. 确认 Milvus 可达（VM 上）: nc 192.168.191.128 19530 或直接试
# 2. 确认本地 MySQL 有 copilot 库（Navicat 看得到）

# 3. 启动 API（订单/知识问答/RAG 都在这里）
uvicorn src.api.app:app --reload --host 0.0.0.0 --port 8000
```

### 方式 B：VM docker（推荐，与面试演示一致）

```bash
# 1. 同步最新代码到 VM
scp -r D:\Rag_project\E-commerce_Customer_Service_System\* root@192.168.191.128:/root/rag-system/

# 2. 确保 Milvus + copilot MySQL 在跑（见下）
ssh root@192.168.191.128 "cd /root && docker compose up -d"           # Milvus
ssh root@192.168.191.128 "docker ps | grep docker-mysql-1"             # copilot MySQL（第二项目）

# 3. 启动 RAG 服务
ssh root@192.168.191.128 "cd /root/rag-system && docker compose -f docker-compose-rag.yml up -d --build"
```

## 4. 切换环境（怎么切）

### 4.1 本地 ↔ VM 数据源切换（.env 里改）

| 参数 | 本地（Windows）| VM |
|------|---------------|-----|
| `MYSQL_HOST` | `127.0.0.1` | `192.168.191.128` |
| `MILVUS_HOST` | `192.168.191.128` | `milvus-standalone`（docker 内）|
| `REDIS_HOST` | `127.0.0.1` | `redis`（docker 内）|

> 本地直跑连本地 MySQL；VM docker 跑时 compose 已注入 `MYSQL_HOST=192.168.191.128`、`MILVUS_HOST=milvus-standalone`，无需改代码。

### 4.2 订单数据源：本地库 vs VM 库

两处数据一致（都灌了 copilot 库）。`MYSQL_HOST` 指哪就连哪。测试建议：
- 本地直跑 → `MYSQL_HOST=127.0.0.1`（本地库）
- VM docker → compose 自动用 `192.168.191.128`（VM 库）

### 4.3 两个项目切换

| 项目 | 本地目录 | VM 位置 | 端口 |
|------|---------|---------|------|
| 电商客服 RAG（本项目）| `D:\Rag_project\E-commerce_Customer_Service_System` | `/root/rag-system` | 8000/7860/7861/7862 |
| 企业运营 Copilot | `D:\Rag_project\enterprise-copilot` | `/opt/enterprise-copilot` | 8000/7860 |

> ⚠️ 两个项目 API 都默认用 8000 端口，**不能同时在 VM 跑两个**（端口冲突）。要换项目，先停另一个：
> `docker compose -f .../docker-compose-rag.yml down` 或 `docker stop docker-api-1`。

## 5. 常见问题

| 问题 | 原因 / 解决 |
|------|------------|
| 订单查询返回"未查询到"| 单号写错或库里没有；真实单号用 `ORD000000001` |
| MySQL Access denied | 确认 .env 的 `MYSQL_USER=agent_ro`、密码 `AgentReadOnly2026` |
| Milvus 连不上 | 先 `cd /root && docker compose up -d`（VM）；或 `MILVUS_HOST` 指向错 |
| 聊天 UI 打开没反应 | 确认 API(8000) + 后端都起来了；UI 是 API 的客户端 |
| 中文乱码（Windows curl）| 用 PowerShell `curl.exe` 或 Python 请求，服务端返回标准 UTF-8 |
